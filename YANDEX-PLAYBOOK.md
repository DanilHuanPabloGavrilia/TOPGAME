# Яндекс.Игры — что проверять до подачи

Записано по итогам трёх отказов модерации на одной игре. Здесь нет ничего про эту
конкретную игру: только требования, ошибки и способы их поймать, которые переносятся в
любой следующий HTML5-проект.

**Как этим пользоваться.** Отдать файл агенту в начале работы над новой игрой и сказать
«проверь по этому списку». Каждый пункт написан так, чтобы по нему можно было выполнить
проверку, а не просто согласиться.

**Оговорка, без которой список опасен.** Требования площадки меняются, а номера пунктов
переезжают. Всё ниже — состояние на август 2026 года, проверенное на живых отказах.
Документацию и чек-лист в консоли разработчика надо открывать заново каждый раз; этот файл
говорит, **куда смотреть и что там обычно ломается**, а не заменяет первоисточник.

---

## Главное, что стоит понять раньше остального

**Отказы приходят не за то, что игра плохая.** Все три раза причиной была не механика и не
качество, а несоответствие формальностям: язык, название, способ подключения SDK,
перетаскивание картинки. Это чинится за часы, но только если знать, где искать.

**Половина замечаний — не в коде.** Тексты полей, обложка, скриншоты, рекламное видео, теги.
Их закрывает владелец, и они занимают столько же времени, сколько программирование.

**Модератор присылает вложения.** PNG и MP4 с записью экрана. Они отвечают на вопрос «что
именно он делал» точнее любой переписки — см. раздел про их чтение.

---

## Требования, на которых спотыкаются

Номера — те, что реально цитировались в отказах. Формулировки пересказаны своими словами.

### п. 1.19.1 — SDK подключается тегом, а не кодом

SDK должен подключаться **так, как показано в документации**: тегом в разметке, до вызова
`YaGames.init()`. Подгружать его скриптом из кода нельзя, даже если для этого есть хорошие
причины.

Причины были: блокирующий тег делает домен площадки единой точкой отказа для первой
отрисовки. Площадку это не интересует. Ставьте тег.

Документация предлагает два пути: абсолютный адрес и относительный `/sdk.js`. Относительный
называется **рекомендуемым для игр, загружаемых через консоль** — то есть для обычного
случая. Он чище: вне площадки просто 404, без шума. Но проверить его можно только на самой
площадке, а если он не отдастся, игра останется без SDK и без определения языка. Решайте
осознанно.

**Что сломается:** тег грузится **везде**, включая дев-сервер. SDK инициализируется, платформа
считает себя боевой, и дальше всё сыплет ошибками рукопожатия, которому не с кем говорить:
реклама и игровые API мертвы, консоль залита. Держите гейт по имени хоста **перед
`init()`**, а не перед загрузкой.

Гейт именно по хосту, а не по флагу дев-сборки: владелец обычно играет на релизной сборке
локально, для неё флаг дев-режима равен false.

### п. 1.19 — GameReady вызывается ровно тогда, когда игра стала доступна

Формулировка в отказе: «вызов GRA осуществляется после того, как игра становится доступной
для взаимодействия».

Документация требует двух вещей одновременно: в момент вызова **все элементы готовы к
взаимодействию** и **экранов загрузки на экране нет**.

**Типичная ошибка:** статическая разметка рисует меню сразу, оно кликается с первого кадра,
а сигнал уходит позже — после инициализации SDK, чтения сохранений и первой отрисовки.
Сигнал всегда отстаёт от первого возможного тапа.

**Правильный порядок:**

1. Непрозрачный экран загрузки поверх всего, **в разметке, до игрового контейнера**;
2. стили подключены в `<head>` и блокируют отрисовку — иначе оверлей будет секунду
   неоформленным и игра просвечивает;
3. загрузка: платформа, язык, сохранения, первая отрисовка;
4. **снять оверлей**;
5. **вызвать `ready()`** — следующей строкой.

**Три страховки, каждая обязательна:**

- снимать оверлей из `finally`, а не из счастливого пути — иначе исключение при загрузке
  оставит игру навсегда за экраном загрузки;
- поставить потолок по времени на рукопожатие с площадкой — зависшее сделает то же самое;
- **удалять узел из документа**, а не гасить прозрачностью. Переход может не отработать
  (усыплённая вкладка, отключённая анимация), и панель повиснет поверх игры непрозрачной,
  но кликаемой насквозь.

Застрявший экран загрузки хуже всего, что он предотвращает.

### п. 1.6.1.8 и 1.6.2.7 — ничего не выделяется и не перетаскивается

Формулировка про «выделение поля или контекстное меню», отдельно для десктопа и для
мобильных. **Почти наверняка это не выделение текста, а перетаскивание картинки** — на
записи видно поднятую копию изображения с курсором «нельзя».

Закрывать надо на трёх уровнях, каждый ловит своё:

```css
* {
  -webkit-user-select: none;   /* без префикса Safari и весь iOS игнорируют */
  -moz-user-select: none;
  -ms-user-select: none;
  user-select: none;
  -webkit-touch-callout: none; /* меню по долгому нажатию на iOS */
  -webkit-user-drag: none;
}
html, body { touch-action: manipulation; } /* двойной тап выделяет подпись кнопки */
```

```js
for (const type of ['contextmenu', 'selectstart', 'dragstart']) {
  document.addEventListener(type, e => e.preventDefault());
}
```

Плюс `draggable="false"` на каждом `<img>`.

**Три ловушки:**

1. **Отсутствие вендорного префикса** у `user-select` — самая частая причина «на десктопе
   чисто, на iOS воспроизводится». Safari годами читал только префиксную форму.
2. **Обработчик на игровом контейнере, а не на документе.** Поля вокруг, отступы и сам
   документ — вне контейнера, и правый клик там открывает меню.
3. **На iOS подъём картинки — нативный жест,** он может не поднимать DOM-событие вообще.
   Обработчик там ненадёжен, атрибут и CSS работают слоем раньше.

Проверьте, что минификатор не выбросил префиксные свойства из собранного CSS. Он умеет.

### п. 2.14 — язык определяется автоматически

Игра обязана стартовать на языке, который назвала площадка. **Ручного переключателя языка в
интерфейсе быть не должно** — требование именно про автоопределение.

Правило выбора: берётся первый источник, который вообще что-то назвал. Если названного языка
в игре нет — **английский, а не язык разработчика**. Родной язык только когда не назвал никто.
Игрок с немецким интерфейсом должен получить английский.

**Язык выбирается дважды.** Статическая разметка рисуется до ответа площадки, поэтому сначала
язык ставится по догадке (браузер), а когда SDK ответит и язык отличается — ставится
настоящий. Функция применения переводов должна быть идемпотентной.

**Шрифты.** Проверьте, что выбранный шрифт вообще умеет нужные алфавиты. Красивые
«игровые» латинские шрифты часто не покрывают ни кириллицу, ни расширенную латиницу
(турецкие `ş ğ ı İ`), ни казахские `ә ғ қ ң ө` — последние это отдельный юникод-блок,
в обычной кириллице их нет. Заголовки молча падают на системный шрифт. Проверяется
замером ширины глифов, а не на глаз.

**Как проверять переводы:** обходом **живой страницы**, а не разметки. Пропускать
`display:none`, `visibility:hidden` **и `opacity:0`** — модалки часто паркуются именно
прозрачностью, и обход без этой проверки отчитается о непереведённом в скрытых узлах.
Прогонять по всем экранам и модалкам. Критерий: ноль чужого алфавита и ноль сырых ключей.

### п. 5.1.3 — название одно и то же везде

Название должно совпадать **в игре и во всех материалах черновика**: в текстовых полях, на
обложке, на скриншотах, в рекламном видео.

Мы насчитали **пять разных вариантов** одного названия: в консоли с подзаголовком, в шапке
игры с эмодзи и в верхнем регистре, в заголовке вкладки с другим подзаголовком, на обложке
с третьим, и слоган под ним. Каждый по отдельности выглядел нормально.

**Как не попасть:**

- Выберите **одну строку** и держите её. Подзаголовок — в описание и SEO, но не в название
  и не в титульный блок обложки.
- **Верхний регистр — через CSS**, а не в разметке. Текстовый узел должен содержать ровно
  зарегистрированную строку.
- **Эмодзи из заголовка убрать.** Молния перед названием — часть текста.
- **Не обрезать название многоточием** на узких экранах. `«MY GAM…»` — это другая строка.
  Лучше спрятать целиком: имя всё равно есть в заголовке вкладки и на главном экране.
- **Апостроф** приведите к одному символу. Прямой `'` и типографский `’` выглядят
  одинаково и являются разными байтами. В словарях это разъезжается само.
- Аффиксы в турецком и узбекском (`Gambit'e`, `Gambit'ga`) — это грамматика, а не второе
  название, их трогать не надо.

### п. 8.2.3 — поля переведены на свой язык

Всё, что меняется в зависимости от языка, должно быть **на этом языке**. Ошибка обычно
глупая: в английский слот залит русский файл обложки, или в русском описании остались
английские слова вроде `ROGUELITE`.

**Проверка на пять секунд:** скачайте обложку из русского и английского слота и сравните
файлы побайтно. У нас они оказались одинаковыми.

### п. 5.4 — теги по делу

Ставить только те теги, которым игра соответствует. Лишние модератор снимет сам, но это
попадёт в список замечаний.

### Из чек-листа в консоли

Перед первой публикацией в консоли есть чек-лист (у нас — 23 пункта), без всех галочек
кнопка отправки не активна. Технические, которые закрываются кодом:

| Что | Как закрывается |
|---|---|
| Контекстное меню | см. выше, вместе с выделением |
| Звук при потере фокуса | `visibilitychange` → заглушить |
| Звук во время рекламы | глушить в колбэке открытия, возвращать в колбэке закрытия |
| Согласие на наградную рекламу | она и так должна быть только за явной кнопкой |
| Сохранения | через API игрока |
| Игра запускалась в черновике | гейт проверяет автоматически, просто откройте её |

Остальное закрывает владелец: возрастной рейтинг, уникальность названия, жанр, описание,
декларация использования ИИ (если код или графика делались с ассистентом — честный ответ
«частично»).

### п. 3.4 и 3.6 — содержание

**Это не техника, и это самый дорогой риск.** П. 3.4 перечисляет запрещённое содержание —
там прямым текстом азартные игры. П. 3.6 требует оригинальной разработки.

Если игра рядом с этими темами, решайте **до** того, как вложитесь в остальное. Обёртка,
локализация и полировка не помогут, если содержание не проходит. И имейте в виду: то, что
пункт не подняли в одном отказе, не значит, что он закрыт.

## Реклама и звук — где обычно течёт

**Наградная реклама в режиме «нет площадки» должна отказывать.** Соблазн выдать награду
безусловно велик — иначе рекламные функции нечем тестировать. Но «нет площадки» это не
только «разработчик за ноутбуком», это ещё и «SDK не поднялся внутри настоящего фрейма».
Кто сумеет сделать домен площадки недоступным, получит неограниченные награды.

Развилка: в дев-сборке выдавать, в релизной — отказывать через колбэк ошибки. **У каждой
точки вызова должен быть обработчик ошибки, который что-то показывает игроку** — иначе
кнопка молча ничего не делает, и это читается как поломка.

**Сторожевой таймер на рекламу обязателен.** Если SDK проглотил вызов и не сообщил ни об
открытии, ни о закрытии, блокировка «реклама идёт» протечёт и заблокирует все следующие.

**Заглушение на время рекламы — отдельный флаг, а не пользовательская настройка звука.**
Переиспользовать её значит перещёлкнуть кнопку под игроком и сохранить чужую настройку.

**Усыпить аудиоконтекст мало** — уже играющий звук продолжится, нужно останавливать и пул
проигрывателей.

**Возобновление звука на мобильных требует пользовательского жеста.** Колбэк рекламы и
событие видимости жестами не являются, поэтому после первой же рекламы игра замолкает
навсегда. Откладывайте повтор на следующий тап и проверяйте **состояние контекста**, а не
обещание, которое умеет резолвиться, ничего не изменив.

**Сторож рекламы снимает блокировку в обход обычного пути** — там заглушение надо снимать
отдельно, иначе не открывшаяся реклама оставит игру немой до конца сессии.

## Сборка и подача — дисциплина, которая стоила отказа

**Первый отказ случился потому, что залитый архив не соответствовал коду.** Разбирались по
датам файлов, потому что поданное состояние нигде не было записано.

**Что делать:**

1. **Собирать только из закоммиченного состояния.**
2. **Ставить тег на то, что подали.** Тогда «а что именно он смотрел» — вопрос одной команды.
3. **Проверять, что архив соответствует коду:** пересобрать в отдельный каталог и сверить с
   тем, что уходит, по SHA-256. Расхождений должно быть ноль. Если сборка детерминирована —
   а она обычно детерминирована, — сам архив хранить не нужно, он воспроизводится из тега.
4. **Пока идёт проверка — не пересобирать** рабочий каталог: это ваша единственная локальная
   копия того, на что смотрит модератор.
5. **Отвечая на отказ, менять только то, за что отказали.** Если в ответ уедет архив с пятью
   изменениями сразу, следующий отказ снова будет нечем объяснить.

**Архив не собирать средствами оболочки по умолчанию.** В PowerShell 5.1 штатная упаковка
пишет пути с обратным слэшем, что нарушает спецификацию ZIP: серверы площадок распаковывают
на Linux, где это читается как имя файла, а не папка, и все ресурсы отдают 404. Собирайте
скриптом, который создаёт записи явно через `/`, **переоткрывает архив и проверяет**: ноль
записей с `\`, точка входа в корне. Не сошлось — архив удаляется, а не уезжает на модерацию.

**Пути в сборке должны быть относительными.** Площадки отдают сборку из подкаталога с хешем,
абсолютные пути от корня там не резолвятся.

**Дев-хуки не должны попадать в релиз.** Проверяется поиском по собранному бандлу, а не
доверием к флагу сборки.

## Тексты витрины — отдельный источник отказов

**Держите их в репозитории, рядом с кодом.** Они расходятся с игрой ровно так же, как архив
расходится с кодом, и лечится это одинаково — записанным источником, который можно сверить.

**Сверяйте каждую цифру с кодом, а не с памятью.** У нас в описании было:

- «12 уникальных карт» при 11 в каталоге — и та же цифра на обложке;
- прокачка, которой **никогда не существовало**, в списке из четырёх при трёх реальных;
- названия предметов и кнопок, написанные по памяти и не совпавшие с тем, что печатает игра.

Ни одно из этих трёх не было в списке замечаний. Их просто не заметили — в этот раз.

**Проверьте переносы строк.** Английские поля у нас потеряли все до единого и шли сплошным
текстом: `roguelike!You wake up at a backroom table`. В русских переносы были на месте.

**Проверьте, что описание не обещает того, чего игра не делает.** У нас выплата за рискованное
действие ограничена пятью разами за бой, а описание обещало её без оговорок. Модератор,
сделавший шестую попытку, увидел бы ноль.

## Как читать вложения модерации

К письму прикладывают PNG и MP4. Они решают вопрос «что именно он сделал» за минуты.

- **PNG** читаются напрямую. При сомнении вырезайте участок и увеличивайте — мелкие
  расхождения (пропавший счётчик в шапке) иначе не разглядеть.
- **MP4** разбирайте на кадры. Если `ffmpeg` нет в PATH, он часто уже стоит внутри
  Python-пакета `imageio_ffmpeg`, который привозит бинарник с собой.
- Кадры берите **чаще в начале** — почти всё интересное происходит в первые секунды
  загрузки.

Пример, ради которого это стоит делать: по кадрам видно, что на 4.0 секунде меню уже на
экране и курсор на кнопке «Играть», а в шапке ещё нет счётчика, который дорисовывается в
конце загрузки. Это и есть доказательство того, что игра стала доступной раньше сигнала
готовности.

## Стенд: как проверить то, что живёт только на площадке

Часть API существует только внутри фрейма площадки. Проверяется так:

1. скопировать точку входа из сборки;
2. вставить заглушку, определяющую глобал SDK, **после настоящего тега SDK**, чтобы она
   его перезаписала;
3. открыть копию **не на localhost** — иначе сработает ваш собственный гейт. Работающий
   приём: подняться на `http://app.localhost:<порт>`. Хост другой, гейт пропускает, всё
   остальное работает как обычно;
4. заглушка пишет вызовы в массив и умеет подставлять язык из параметра адреса — так
   проверяются и последовательность вызовов, и все переводы;
5. файлы стенда удалить до упаковки и **проверить, что их нет в архиве**.

Это единственный способ увидеть, что сигнал готовности приходит ровно один раз и после
снятия экрана загрузки.

## Чек-лист перед подачей

Технику проверяет агент, витрину — владелец.

**Код**

- [ ] SDK подключён тегом в разметке, как в документации; из кода не подгружается
- [ ] гейт по имени хоста стоит перед инициализацией, а не перед загрузкой
- [ ] экран загрузки непрозрачен с первого кадра, стили блокируют отрисовку
- [ ] сигнал готовности уходит после снятия оверлея, из `finally`, с потолком по времени
- [ ] оверлей удаляется из документа, а не гасится прозрачностью
- [ ] выделение, контекстное меню и перетаскивание подавлены на документе, всеми префиксами,
      плюс `draggable="false"` на картинках
- [ ] префиксные CSS-свойства уцелели в собранном виде
- [ ] язык определяется автоматически, ручного переключателя нет; неизвестный язык → английский
- [ ] шрифт покрывает все алфавиты, которые вы возите
- [ ] обход живой страницы: ноль чужого алфавита, ноль сырых ключей, на всех экранах
- [ ] звук глохнет при потере фокуса и во время рекламы; возвращается после жеста
- [ ] наградная реклама в релизе без площадки отказывает; у всех точек есть обработчик ошибки
- [ ] дев-хуков в собранном бандле нет
- [ ] пути относительные
- [ ] архив: записи через `/`, точка входа в корне, совпадает с пересборкой по SHA-256
- [ ] на поданное состояние поставлен тег

**Витрина**

- [ ] название — одна строка, совпадает в игре, в консоли, на обложке, на скриншотах и в видео
- [ ] в каждом языковом слоте текст на этом языке; файлы обложек в слотах **разные**
- [ ] цифры в описании сверены с кодом
- [ ] описание не обещает того, чего игра не делает
- [ ] переносы строк на месте во всех языках
- [ ] теги соответствуют игре
- [ ] возрастной рейтинг и содержание продуманы заранее
- [ ] скриншоты нужных размеров (уточнить в консоли **до** съёмки — растянутый кадр завернут)
